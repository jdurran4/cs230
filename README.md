# CS230: Learned Source Terms for Unresolved Immersed Bodies

Code for my CS230 (Deep Learning) final project. Small immersed bodies such as cables
force heavy mesh refinement in CFD. This project trains a neural network to stand in for
a body the coarse mesh can't resolve: the body is removed, and the network supplies the
force it would have put on the flow, as a momentum source in each coarse cell.

The test problem is quasi-2D supersonic flow (M 1.2–2.5, Re_D 20–200) past a stationary
cylinder in the compressible solver AERO-F:

1. **Resolved runs.** The cylinder is an embedded boundary with adaptive mesh refinement.
   A run gives the true force on the body over time, from an impulsive start.
2. **Coarse oracle runs.** The resolved force is binned into the dual cells of a coarse
   mesh (D/h = 0.6–4.8, where h is the cell size). Then the run is replayed on that mesh
   with no cylinder and the true source applied from a file. Training inputs come from
   these runs, i.e. the coarse states the solver will actually see online.
3. **Network.** A small MLP maps the local coarse state and the cell's geometry (Mach
   vector, Reynolds number, volume fraction, surface normal, body offset, D/h) to the
   per-cell source. It predicts a residual on top of the local pressure force.
4. **Online.** The network is coupled into AERO-F and replaces the oracle file.

Results (see the report): the 2×64 MLP gives 2–3× lower held-out per-cell error than
linear regression. Online, on a held-out case, it reproduces the shock and wake and gets
drag within 2% of the resolved run, at 217× lower CPU cost.

## What is and isn't in this repo

This repo holds the Python and shell code: case generation, binning, datasets, training,
baselines, and the figure scripts. **It cannot be run end to end on its own**:

- **AERO-F** (Stanford FRG's flow solver) is not public. The neural and oracle source
  terms are C++ changes in the lab's AERO-F repository, not here. `online/check.py` is
  a line-for-line Python reference of the C++ source term.
- **Data** (resolved runs, oracle runs, datasets, trained weights: ~850 GB) is not
  included. The scripts read it from `~/Research/cs230-data/` (override with the
  `CS230_DATA` environment variable).
- The steady resolved sweep (`steady-v0/`, ~300 cases that add coverage of the settled
  flow) was generated by an earlier version of the code, kept in the `steady-v0` git tag.

Each script starts with a docstring covering what it does, what it reads and writes, and
how to run it.

## Setup

Python 3.12 with numpy, matplotlib and PyTorch (`pip install -r requirements.txt`). Run
everything from the repo root as modules, e.g. `python -m learn.train cv`.

## Layout

- `common.py`: data paths, gas constants, AERO-F file readers.
- `sweep/`: AERO-F case setup and running
  - `meshGen.py`, `preprocess.sh`: coarse background mesh and embedded cylinder
  - `newRun.py`, `FluidFile_template`, `runTemplate/`, `runSweep.sh`: unsteady resolved
    runs (one directory per (M, Re, cylinder position) case)
  - `oracle.py`, `OracleFluidFile_template`, `SteadyOracleFluidFile_template`,
    `oraclePreprocess.sh`, `runOracles.sh`: coarse oracle runs (binned true source on
    the coarse mesh)
  - `meshSweep.sh`: the mesh-size study (oracles + datasets on D/h 0.6, 1.2, 2.4, 4.8)
  - `online.py`: online runs with the network source
  - `tools.sh`: AERO-F tool paths (lab cluster / workstation; edit for your machine)
- `learn/`: datasets and training
  - `dataset.py`: one row per body cell per snapshot (coarse oracle state, geometry,
    true source)
  - `features.py`: network inputs and targets
  - `train.py`: cross-validation (folds by case), y-mirror augmentation, and the weights
    export that AERO-F reads
  - `baselines.py`: pressure-only and linear-regression baselines, scored like `train.py`
  - `pilot3d.py`: 3D median-dual binning (used by `dataset.py` and `oracle.py`)
  - `slideAccuracy.py`: a priori accuracy figure and numbers
- `online/`: checking coupled runs
  - `check.py`: Python reference of AERO-F's neural source
  - `unsteady.py`: online vs. oracle forces and field error for one case
  - `slideFigures.py`: force-history and wake figures
  - `pngsToMp4.sh`: ParaView frames to a movie

## Pipeline

```
python -m sweep.meshGen && sweep/preprocess.sh       # coarse mesh + cylinder
python -m sweep.newRun && sweep/runSweep.sh          # resolved runs (AERO-F)
sweep/meshSweep.sh                                   # oracle runs + datasets, every D/h
python -m learn.train cv --mirror --data coarse_unsteady_Dh1.2.npz ...   # CV
python -m learn.baselines --mirror --data ...        # baselines on the same folds
python -m learn.train export --mirror xy NAME --data ... --exclude CASE  # weights
python -m sweep.online --Dh 1.2 CASE NAME            # online run (AERO-F)
```
